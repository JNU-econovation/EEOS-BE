# GitHub 이슈 생성 스킬

## 동작 순서

### 1단계: 이슈 유형 선택

사용자에게 이슈 유형을 묻는다.

```
어떤 유형의 이슈인가요?

1) 버그 리포트
2) 기능 요청
3) 취소
```

### 2단계: 컨텍스트 수집

현재 작업 컨텍스트를 파악하기 위해 다음 명령어를 **병렬로** 실행한다.

```bash
git branch --show-current          # 현재 브랜치명
git log --oneline -10              # 최근 커밋 목록
git diff HEAD --stat               # 현재 변경 파일 목록
```

### 3단계: 이슈 초안 작성

이슈 유형에 따라 `.github/ISSUE_TEMPLATE/` 의 템플릿을 기반으로 초안을 작성한다.

**버그 리포트 템플릿 (`bug-report.md`) 양식:**
```
## 어떤 이슈인가요?
{버그 현상 설명}

## 왜 발생했나요?
> 가능하면 given-when-then 형식으로 서술해주세요.
{원인 분석}

## 어떤 해결방법들이 있나요? / 어떻게 해결했나요?
{해결 방법}

## 참고할만한 자료(선택)
{관련 링크/자료}
```

**기능 요청 템플릿 (`feature_request.md`) 양식:**
```
## 어떤 기능인가요?
> 추가하려는 기능에 대해 간결하게 설명해주세요
{기능 설명}

## 작업 상세 내용
- [ ] TODO
- [ ] TODO
- [ ] TODO

## 참고할만한 자료(선택)
{관련 링크/자료}
```

**제목 규칙:**
- 70자 이내
- 이슈 유형을 prefix로 붙인다: `[Bug]` 또는 `[Feature]`
- 핵심 내용을 간결하게 표현

### 4단계: 사용자에게 초안 제시 및 피드백 요청

```
📋 이슈 초안:

제목: {이슈 제목}
유형: {버그 리포트 / 기능 요청}

---
{이슈 본문}
---

1) 그대로 이슈 생성
2) 내용 다시 작성
3) 취소
```

### 5단계: 피드백에 따른 처리

**1번 선택 시** — 이슈를 생성한다.
- `gh issue create` 로 이슈를 생성한다.
- 버그 리포트는 `--label "bug"`, 기능 요청은 `--label "enhancement"` 를 붙인다. (라벨이 없으면 생략)
- Assignee를 현재 GitHub 계정으로 설정한다: `--assignee @me`
- 생성된 이슈 URL을 출력한다.

**2번 선택 시** — 어떤 부분을 수정할지 사용자에게 물어본 뒤 다시 작성하여 4단계로 돌아간다.

**3번 선택 시** — 이슈 생성을 취소하고 종료한다.

## 주의사항

- 이슈 제목과 본문은 **반드시 한글**로 작성한다.
- `gh` CLI가 인증되어 있지 않으면 사용자에게 `gh auth login` 을 안내한다.
- 사용자가 이슈 내용을 직접 설명한 경우, 그 내용을 최대한 반영하여 초안을 작성한다.
- 라벨이 해당 저장소에 존재하지 않을 수 있으므로, 라벨 추가 실패 시 라벨 없이 생성한다.
